# Запуск для демонстрації

Окремий запуск платформи на один день: без домену і сертифікатів, звичайний HTTP,
назовні відкритий один порт. Не використовує порти 80, 443, 8000 і 5433, тому не заважає
іншим проектам на тому самому сервері.

## Що потрібно на сервері

- Docker з плагіном compose;
- 4 ГБ оперативної пам'яті (мінімум 2 ГБ і swap);
- близько 5 ГБ вільного місця на диску;
- відкритий порт для демонстрації (за замовчуванням 8080).

## Запуск

```bash
git clone https://github.com/iBarzha/sql-learning-platform.git
cd sql-learning-platform
git checkout feature/admin-dashboard
./demo-up.sh
```

Інший порт: `DEMO_PORT=9000 ./demo-up.sh`.

Перший запуск триває 5-10 хвилин, бо збираються образи. Наприкінці скрипт друкує адресу
і пароль. Пароль один для всіх демо-акаунтів, генерується випадково і зберігається
у файлі `.env.demo`.

## Акаунти

| Роль | Пошта |
|---|---|
| Адміністратор | admin@test.com |
| Викладач | instructor@test.com |
| Студент, уже записаний на курс, має історію відповідей | student@test.com |
| Студент, ще не записаний на жоден курс | student2@test.com |

Коди курсів: `SQLDEM` (SQL, PostgreSQL) і `MNGDEM` (MongoDB).

## Що показати

1. Адміністратор: панель, список користувачів, створення акаунта з тимчасовим паролем.
2. Викладач: курс "Бази даних: мова SQL", редагування уроку, приховані набори даних у вправі
   "Кількість працівників у відділах", кнопка перевірки наборів, результати студентів.
3. Студент student2: приєднання до курсу за кодом `SQLDEM`, урок з теорією, практика.
4. Оцінювання на вправі "Кількість працівників у відділах":

   | Відповідь | Бал |
   |---|---|
   | `LEFT JOIN` з `COUNT(e.id)` | 100 |
   | `JOIN` замість `LEFT JOIN` | 50, бо губиться відділ без працівників |
   | результат, вписаний вручну через `SELECT ... UNION ALL` | 0 |

5. Вправа "Рейтинг зарплат": правильні рядки в неправильному порядку дають 82.35.
6. Урок "Зміна даних": перевіряється стан таблиць після UPDATE, INSERT, DELETE.
7. Контрольна робота: таймер 20 хвилин не скидається після оновлення сторінки, 3 спроби на завдання.
8. Пісочниця: п'ять СУБД, готові набори даних.

Опис алгоритму оцінювання: [GRADING_ALGORITHM.md](GRADING_ALGORITHM.md).

## Дані зі старого сервера

Замість чистої бази можна підняти дамп, знятий зі старого сервера:

```bash
DEMO_DUMP=/шлях/до/sql_learning.sql ./demo-up.sh
```

Міграції застосуються поверх дампа, демо-курс буде додано до наявних, а демо-акаунтам
буде встановлено пароль із `.env.demo`. Файл дампа містить хеші паролів, тому в репозиторій
його додавати не можна.

## Корисні команди

```bash
# стан сервісів
docker compose --env-file .env.demo -f docker-compose.demo.yml ps

# журнал бекенду
docker compose --env-file .env.demo -f docker-compose.demo.yml logs -f backend

# створити демо-курс заново
docker compose --env-file .env.demo -f docker-compose.demo.yml exec backend python manage.py seed_demo --reset
```

## Після демонстрації

```bash
./demo-down.sh
```

Видаляє контейнери, томи з даними, зібрані образи і файл `.env.demo`.
